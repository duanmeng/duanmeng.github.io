Velox Type System

duanmeng
2022-06-07
technology
QueryExecution, SIMD, data, paper, vectorized, velox

Velox 的类型系统要同时回答三件事：值的逻辑含义是什么、执行代码用哪种 C++ 表示、一个 batch 实际如何存储。这三个问题分别落在 Type、TypeTraits / NativeType 和 Vector 上，不能只看一个 TypeKind 就结束判断。

本文于 2026-09-19 对照 Velox 1d1b76567870 重写，重点补齐逻辑类型、类型比较、复杂类型、null 和编码之间的关系。

1. Type、TypeKind、NativeType、Vector

层次 回答的问题 例子
TypeKind 执行分派所需的基本类别 INTEGER、BIGINT、ROW
Type / TypePtr 完整逻辑结构与参数 DATE、DECIMAL(12,2)、ROW(a BIGINT)
TypeTraits / NativeType 对应 C++ 表示与编译期属性 BIGINT → int64_t
Vector 一批值的编码、buffer、null 与长度 FlatVector、DictionaryVector、LazyVector

TypePtr 是 std::shared_ptr<const Type>。Type 是共享的只读类型描述，不保存某个 vector 的实际数据，也不代表某个 SQL 值。原始定义见 TypePtr、TypeKind。

把一列 BIGINT 包成 dictionary，类型仍是 BIGINT；把 INTEGER 改成 DATE，即使底层同为 int32，逻辑类型已经改变。类型判断和编码判断必须分开。

2. 基本类型与逻辑覆盖类型

TypeKind 包括 BOOLEAN、整数、浮点、VARCHAR、VARBINARY、TIMESTAMP，以及 ARRAY/MAP/ROW/UNKNOWN/FUNCTION/OPAQUE 等。枚举里没有单独的 DATE 或 DECIMAL 项。

逻辑类型 kind 常用 NativeType 不能丢失的信息
BIGINT BIGINT int64_t 整数语义
DATE INTEGER int32_t 以天为单位的日期语义
DECIMAL(1..18,s) BIGINT int64_t precision、scale
DECIMAL(19..38,s) HUGEINT int128_t precision、scale
VARCHAR / VARBINARY 各自独立的 kind StringView 文本与字节串语义不同
TIMESTAMP TIMESTAMP Timestamp 秒与纳秒的时间表示

DATE 继承 IntegerType，却通过具体类型身份区别于 INTEGER。DECIMAL 的 precision 和 scale 也会参与等价判断。参见 DecimalType、DateType。

DECIMAL(12,2) 的数值可理解为“存储整数 × 10^-2”；precision 限制十进制总位数，scale 限制小数位数。短/长 decimal 的分界是 precision 18/19，最大 38。只拿到 int64_t 不能推回它是 BIGINT、DECIMAL 还是其他基于 BIGINT 的逻辑类型。

字符串的 StringView 是值的轻量表示，不应等同于一段总是自行拥有的 std::string；长字符串需要相应的 buffer 生命周期。Vector 与 RowContainer 的存储所有权是另一层问题。

3. 复杂类型是一棵有参数的树

Type 继承 Tree<const TypePtr>。ARRAY 有一个元素子类型；MAP 有 key/value 两个子类型；ROW 包含按顺序排列的字段类型与字段名。参见 ArrayType、MapType、RowType。

Type::size() 对复杂类型表示子类型数量，不能当成列的行数。行数由 BaseVector::size() 表示。cppSizeInBytes() 也不能用于估算整个 ARRAY、MAP 或 VARCHAR 列的内存占用。

null 不写在 TypeKind 里

同一个 BIGINT Type 可以对应有 null 或无 null 的 Vector。null 是数据状态，通常由 vector 的 null bitmap 表示；Array/Map/Row 自身为 null，与某个元素/子字段为 null，也是不同层次。

UNKNOWN 是独立的类型类别，常见于未定型 null 等场景。它不是所有 Type 的“可空包装”。读取复杂值时，要同时处理外层 null、offset/size 和子向量中的 null。

4. 类型相同到底是什么意思

这是实际编码时最容易出错的部分。当前实现提供三种不同强度的比较：

接口 比较内容 适用判断
kindEquals 递归比较 TypeKind 表示类别是否一致
equivalent 逻辑类型及参数；ROW 忽略字段名 忽略字段名后是否等价
operator== / equals 强匹配；包含 ROW 字段名和 OPAQUE 身份 完整类型是否相同

不要用 TypePtr 地址相等替代上述接口。部分简单类型使用单例，部分带参数类型会独立创建；共享地址是实现细节。

当前代码与 类型比较测试 可以得到：

A 与 B kindEquals equivalent *A == *B
DATE 与 INTEGER true false false
DECIMAL(10,2) 与 DECIMAL(12,2) true false false
ROW(a BIGINT) 与 ROW(b BIGINT) true true false
ARRAY(BIGINT) 与 ARRAY(INTEGER) false false false

RowType::equivalent 递归比较 child 的等价关系；RowType::equals 还比较同位置字段名，当前实现区分大小写。参见 ROW 两种比较。

标准 OpaqueType::create<T>() 之间的 equivalent 不比较 T 的 type_index，而 equals 会比较。因此 opaque 的 weak match 不能作为安全转换任意 C++ 对象的依据。参见 OPAQUE 比较。

hashKind() 与 hash() 也需要区分。前者按 kind 递归计算，允许不同逻辑类型碰撞；后者与强匹配一致，考虑 ROW 名字、DECIMAL 参数、OPAQUE 身份等。自定义类型若改变相等关系，必须维持“相等对象 hash 相同”的约束。

最易读的方式是使用命名工厂：

泛型代码可以使用 TypeFactory<KIND>、Type::create<KIND> 或 createType(kind, children)。但仅提供 kind 和 children 无法恢复 decimal 的 precision/scale、原始 ROW 字段名或自定义逻辑类型；遇到这些类型要使用完整参数或完整序列化描述。参见 createType 接口。

反方向的 CppToType<T> 是模板特化表，不是能推导所有 C++ 容器和业务对象的反射系统。当前 CppToType 中：

  • int64_t / uint64_t 都映射到 BIGINT；不意味着 Velox 增加了一个 SQL unsigned BIGINT。
  • StringView、std::string、std::string_view 都映射到 VARCHAR。
  • VARBINARY 也使用 StringView，但没有另一个相同 T 的特化；要显式选择 VARBINARY。
  • shared_ptr<T> 通过 OpaqueType::create<T> 构造 opaque。
  • 普通 int32_t 无法推导 DATE，int64_t 无法推导 DECIMAL(p,s)。

这是一种有损映射：多个逻辑类型共享一个 NativeType，因此“从 C++ T 推导”不可能自动恢复全部 schema。

6. 类型分派与 Vector 访问

TypeKind 可以把运行时分派转成模板实例化，例如在 INTEGER/BIGINT/DOUBLE 等分支中选定 TypeTraits<KIND>::NativeType。这是执行内核获得静态 C++ 类型的入口，但它仍需处理 logical overlay 的语义约束。

同样，确定类型为 BIGINT 后，不能直接把任意输入当作 FlatVector<int64_t> 取裸值数组。输入可能是 constant、dictionary 或 lazy。应选择支持这些编码的接口，或通过 DecodedVector 取得底层向量、索引映射和 null 信息。参见 DecodedVector。

例如 dictionary 的逻辑行 i 指向 base 的 indices[i]；两层 dictionary 还会组合索引。DecodedVector 通常帮助解开这种映射，不代表无条件复制并展平整列。编码转换成本、lazy 加载和 null 传播，是 Vector 层的职责。

7. 自定义类型、序列化和兼容性

Velox 允许定义基于已有表示的逻辑类型，以及 OPAQUE 等扩展。但“注册了类型名”并不自动获得所有 cast、比较、hash、函数签名与序列化支持。

实际扩展时应分别确定：基础 kind / native storage、类型参数、equivalent / equals / hash、类型描述的 serde、值的 serde，以及参与哪些函数和算子。尤其是 opaque，进程内 shared_ptr 的地址不能成为跨进程的值协议；其类型序列化也依赖注册的稳定名称。参见 OpaqueType::serialize。

类型相等也不等于“允许隐式转换”。INTEGER 与 BIGINT 可以在某些语义下 coercion，但仍不是相等类型。转换与公共类型推导应查看 TypeCoercer 及具体函数/宿主使用的规则，不能用 equivalent 代替 SQL coercion。

8. 阅读与验证入口

最有效的顺序是：TypeKind / TypeTraits → Type 接口与具体类 → 复杂类型比较实现 → CppToType → DATE、DECIMAL 与比较测试。
