SIMD Basic Using AVX and AVX2

duanmeng
2021-08-22
technology
C++, SIMD

写 AVX/AVX2 代码，难点往往不是找到一个 intrinsic，而是回答五个问题：数据怎样进入寄存器、每条指令实际操作哪些元素、条件怎样表示、尾部怎样安全处理，以及为什么这段代码会更快。 本文按这条顺序建立编程模型，再给出可编译、带运行时分派和边界检查的完整示例。

2026-09-19 全面重写。示例面向 x86-64、C++17、GCC / Clang，分别标明 AVX、AVX2、FMA 要求。文末提供完整源码和实际验证记录；不要求读者安装 Velox。

1. SIMD 的执行模型：一条指令，多份数据

SIMD 把同一种操作应用到多个元素。例如把 8 个 float 装入一个 256 位寄存器，_mm256_add_ps(a, b) 对应 out[i] = a[i] + b[i]，其中 i=0..7。这是寄存器内的数据并行，不等同于创建 8 个线程，也不意味着整个循环一定加速 8 倍。

类型 常见解释 元素数
__m128 / __m256 32 位 float 4 / 8
__m128d / __m256d 64 位 double 2 / 4
__m128i / __m256i 8、16、32、64 位整数或位串 16/32、8/16、4/8、2/4

__m256i 自身没有“这是 uint32 还是 int16”的运行时标签。具体 intrinsic 决定如何解释这些位。位与、相等比较、低位加法通常不区分符号；大小比较、扩宽和饱和运算则必须选对有符号 / 无符号版本。

在 x86-64 中，YMM 的低 128 位与同编号 XMM 重叠。AVX 使用 VEX 编码，许多运算支持独立的两个输入和一个输出；编译器把 C++ 中的向量变量分配到寄存器，变量并不固定对应某一个 YMM。

256 位不代表任意元素都能互相交换

本文用“元素 lane”表示一个 float / integer 位置，用“128 位子块”表示 YMM 的低半与高半。许多 AVX/AVX2 shuffle、unpack、pack、horizontal 指令在两个 128 位子块内分别工作；另一些 permute 可以跨越中间边界。

这条区别会影响重排、求和、压缩和查表。只记住寄存器总宽度，往往会写出“低半对了，高半顺序错了”的代码。

2. AVX、AVX2、FMA 与编译选项

能力 代表操作 编译 / 运行要求
AVX 256 位 float / double 算术，浮点比较、load/store、部分重排 AVX 与操作系统的扩展寄存器状态支持
AVX2 广泛的 256 位整数算术、整数比较、变量移位、gather、更多重排 AVX2
FMA3 a*b+c 等单次舍入的融合运算 单独的 FMA 特性，常用 -mfma
POPCNT / BMI 等 标量 bit count、bit manipulation 各自独立的 CPU 特性；不能只凭 AVX2 名称推断

__m256i 类型和 256 位整数 load/store 的存在不代表 AVX 已支持所有 256 位整数运算。类似地，FMA 不属于 AVX2 的必然组成部分，需要独立检查。AVX-512 的 mask registers、compress / scatter 等也不能直接套到 AVX2 上。

Intrinsic 是编译器接口，不是机器指令清单的一比一别名

常见命名形如 _mm256_add_epi32：256 提示向量宽度，add 是操作，epi32 描述元素解释。但不能机械地说前缀总是返回值宽度：_mm256_movemask_epi8 返回标量 int；某些 conversion 的输入与输出宽度不同。

set、setr、cast 等 intrinsic 可能变成常量加载、多条指令或不产生指令；算术 intrinsic 也可能与加载合并，或被编译器优化掉。看实际生成代码，才能判断执行了什么。

两种编译方式

如果程序只在已知支持 AVX2 的机器运行，可对专用目标使用 -mavx2；使用 FMA 再加 -mfma。这会允许编译器在整个目标中生成相应指令，包括看起来“只是标量”的代码。

3. 元素顺序、常量与内存布局

本文把数组低地址和元素 0 画在左边。通过 load 从 a[0] 读入后，lane 0 就对应 a[0]；通过 store 写回也按相同顺序。Little endian 决定单个多字节元素内部的字节顺序，不会自动把数组元素倒序。

set 的参数从高 lane 写到低 lane；setr 按 lane 0 开始排列，适合展示索引。set1 广播一个值；setzero 生成全零。64 位整数构造的常用确切名字是 _mm256_set_epi64x、_mm256_setr_epi64x、_mm256_set1_epi64x，不要把所有后缀都机械地拼成 epi64。

调试时先 store 到正确类型的数组再打印。不要依赖把向量对象地址直接转成 float* / int* 后解引用，这会把编译器扩展、对象表示与 C++ aliasing 规则混在一起。

AoS 与 SoA 决定了数据搬运成本

struct Point { float x, y, z; }; 的数组是 AoS，8 个 x 分散在内存中；分别保存 x、y、z 的数组是 SoA，8 个 x 连续。若热点只处理 x，SoA 常能省掉 gather 或 shuffle；若每次都完整消费一个对象，AoS 可能更合适。

SIMD 优化经常首先是布局优化。为了省一条乘法而引入大量跨 lane 重排或散乱访存，未必划算。

4. Load、Store、对齐与尾部

操作 例子 契约
连续未对齐加载 / 存储 _mm256_loadu_ps / _mm256_storeu_ps 地址无需 32 字节对齐，但完整 32 字节范围必须可读 / 可写
连续对齐加载 / 存储 _mm256_load_ps / _mm256_store_ps 地址需要 32 字节对齐；整数版为 load / store_si256
浮点 maskload / maskstore _mm256_maskload_ps / _mm256_maskstore_ps AVX；每个 mask 元素最高位决定是否访问
整数 maskload / maskstore _mm256_maskload_epi32 / _mm256_maskstore_epi32 AVX2；支持 32 / 64 位元素
Gather _mm256_i32gather_epi32(base, index, 4) AVX2；地址为 base + 有符号 index × scale，scale 取 1、2、4、8

alignas(32) 只保证对象起点；对齐数组的 a+1 通常不再 32 字节对齐。loadu 也可以用于恰好对齐的地址，现代 CPU 上实际成本还受跨 cache line / page、缓存命中和微架构影响，不能简单说“未对齐总是慢两倍”。

第一个完整循环：数组相加

下面要求三个数组各有 n 个元素；输出可与某一个输入完全重合，但不支持任意的部分重叠。若业务允许部分重叠，需要单独定义遍历方向或缓冲策略。

n-i >= 8 保证每次完整访问 8 个 float，也避免 i+8 在极端 size_t 值上溢出。小于 8 个元素时直接进入标量循环。大多数算法先写出这种可验证的尾部，再考虑 maskload 或带 padding 的专门契约。

Maskload 的掩码不是 0/1 布尔数组

每个 32 位 mask 的最高位为 1 才启用该元素，例如全 1 的 -1；数值 1 的最高位为 0，反而不加载。禁用位置的 load 结果为零；maskstore 对禁用位置不写入，而不是写零。

输入只需有 count 个可读元素，但这里 out8 必须容纳完整 8 个元素。禁用 lane 不进行相应架构内存访问；仍应按 intrinsic 文档构造有效的启用地址，并注意 sanitizer 未必能完整建模每一种掩码访存。完整测试还把尾部放在不可访问页之前检查。

先完整 load，再 blend 掉多余元素，不能修复已经发生的越界。 AVX2 也没有通用的 8/16 位 maskload；字节尾部可标量处理，或复制到清零的局部 32 字节缓冲再加载。

Gather 解决地址表达，不保证更快

Gather 的索引决定各元素地址，scale 是字节倍率，不是“元素数量”。使用 int32 索引配 32 位元素时常用 scale=4。AVX2 的 gather 返回宽度与元素 / 索引组合有关，不是每一种都返回 8 个结果；还要查确切签名。

Gather 无法把随机内存访问变成连续访问。一批数据可能触及多条 cache line、多个页面，收益取决于缓存和地址分布。AVX2 没有对应的通用 scatter store；散乱输出常需要标量写回或改变布局。

5. 算术：整数溢出、乘法与 FMA

整数加减有模运算与饱和两类

_mm256_add_epi32 按每个 32 位元素做模 2³² 的加法；低位结果对有符号 / 无符号解释相同。C++ 标量有符号溢出却是未定义行为，所以写 scalar reference 时应使用 unsigned，或先扩宽再计算。

adds/subs 是饱和加减，AVX2 常用版本针对 8 位和 16 位，分 signed / unsigned。不能推导出不存在的 _mm256_adds_epi32。例如 uint8 的 250+20，普通 add 保留低 8 位得到 14，饱和 add 得到 255。

32 位乘法必须先问：需要哪几位、哪几个元素

Intrinsic 实际结果
_mm256_mullo_epi32 全部 8 对 int32 相乘，每对只保留低 32 位
_mm256_mul_epi32 选输入元素 0、2、4、6，做 signed 32×32→64，返回 4 个结果
_mm256_mul_epu32 同样选 0、2、4、6，做 unsigned 32×32→64
_mm256_mulhi_epi16 / _mm256_mulhi_epu16 保留 16×16 乘积的高 16 位，符号语义不同

mul_epi32 不是“计算前四个元素”。若要 8 个完整 64 位乘积，可以分别处理偶数元素和移动后的奇数元素，再按需要组织输出。AVX2 没有通用的 packed integer divide，也没有通用的 256 位逐元素 64×64→低64乘法 intrinsic；需要分解、标量路径或更高 ISA 的对应能力。

浮点比较、除法与近似指令要保留语义

add/mul/div_ps 分别操作 8 个 float；pd 操作 4 个 double。rcp_ps、rsqrt_ps 是近似倒数 / 倒平方根，不能无条件替代除法或 sqrt；误差、特殊值和 refinement 的需求取决于业务。

min/max 对 NaN、相等值和有符号零的行为不能只凭名字类比 std::min 或 std::fmin。涉及 NaN、±0、舍入模式、subnormal 时，需要查对应指令语义。-ffast-math 允许更激进的变换，不只是“让程序更快”的开关。

FMA 只有一次最终舍入，但结果可以改变

FMA 计算 round(a*b+c)，分离乘加通常计算 round(round(a*b)+c)。例如 float 中取 a=1+2^-23、b=1-2^-23、c=-1：分离乘加可得到 0，而 FMA 保留结果 -2^-46。

FMA 常有利于精度与吞吐，但不会自动让整个算法更快，也不保证与原表达式逐位相同。若主体用 FMA、尾部也要求相同单次舍入语义，标量尾部应使用 std::fma。本文测试使用 -ffp-contract=off 控制普通乘加的自动融合，显式 FMA intrinsic 不受此禁止融合设置替代。

fmaddsub 的偶数 lane 减、奇数 lane 加；fmsubadd 相反。不要只看名称而忽略交替方向。

6. 比较、Mask 与无分支处理

AVX/AVX2 常规比较生成普通向量 mask：true 是该元素所有位为 1，false 是所有位为 0。它不是 AVX-512 的 k-mask 寄存器。

浮点比较使用带谓词的 _mm256_cmp_ps(a, b, imm)。例如 _CMP_GT_OQ 表示 ordered、greater-than、quiet：任一输入为 NaN 时该位置为 false。Quiet 指的是对 quiet NaN 的异常行为，不代表 signaling NaN 在所有情况下都不会引发 invalid。

整数常见比较有 cmpeq 和 signed cmpgt。对 uint32 做大于比较时，可以先把两个输入都 XOR 0x80000000，将无符号顺序映射为有符号顺序，再用 _mm256_cmpgt_epi32。

Movemask 与 blend 服务于不同的控制方式

  • _mm256_movemask_ps 提取 8 个 32 位元素的最高位，返回低 8 位 bitset。
  • _mm256_movemask_epi8 提取 32 个字节的最高位。对 int32 比较结果直接使用它，每个 true 元素会产生连续 4 个置位 bit。
  • _mm256_blendv_ps(a,b,mask) 根据每个 float mask 元素的最高位，选 a 或 b；blendv_epi8 则按每个字节选择。
  • 位运算选择可写成 (mask & b) | (~mask & a)，前提是相应选择范围内 mask 确实为全 1 / 全 0。

Blend 不短路执行。两侧表达式、分配或加载若已提前执行，不会因为最终未被选中就免除其成本或异常。真正按条件访问内存，需要合适的 masked memory 指令或分支。

完整模式：统计大于阈值的 uint32

_mm256_castsi256_ps 只重新解释位，不把整数数值转换为 float，也无需发出数值转换指令。它让 movemask 对每个 int32 mask 只取一个 bit。示例用清最低置位 bit 的循环计数，避免引入额外 POPCNT ISA 前提；需要更高吞吐时，可根据特性检查和实测换成 popcount 或向量计数策略。

同样的 bitset 还可用于“是否任意命中”“是否全部命中”“首个命中位置”或输出选择索引。调用 __builtin_ctz 之类的接口前必须排除零；它们并不都为零输入定义结果。

7. Shuffle、Permute、Unpack：先画索引再写 immediate

把输入写成 [a0,a1,a2,a3 | a4,a5,a6,a7]，中线表示 128 位边界。以下规律是 AVX/AVX2 最值得记住的部分：

Intrinsic 控制方式 可选范围
_mm256_permute_ps immediate，四组 2-bit 选择器 每个 128 位子块内的 4 个 float，同一规则作用于两半
_mm256_shuffle_ps(a,b,imm) immediate 每半输出前两项取 a，后两项取 b；仍不跨中线
_mm256_permute2f128_ps immediate 从 a.low / a.high / b.low / b.high 选择两个 128 位块，也能置零
_mm256_permutevar8x32_epi32 / _ps 8 个运行时索引 AVX2；各输出在完整 8 个 32 位元素中选择，索引低 3 位有效
_mm256_permute4x64_epi64 / _pd immediate AVX2；在完整 4 个 64 位元素中选择
_mm256_shuffle_epi8 每字节一个控制字节，不是 immediate AVX2；各 128 位子块内的 16 字节，支持置零
_mm256_shufflelo_epi16 / _shufflehi_epi16 immediate 分别重排每个 128 位子块的低 4 / 高 4 个 word，其余不变

_MM_SHUFFLE 从右边决定 lane 0

_MM_SHUFFLE(z,y,x,w) 等价于 (z<<6)|(y<<4)|(x<<2)|w。例如：

对 _mm256_shuffle_ps(a,b,_MM_SHUFFLE(3,2,1,0))，结果是 [a0,a1,b2,b3 | a4,a5,b6,b7]。所有四组选择位都有意义，不能说只使用 immediate 的高四位。

需要运行时变化的索引时，不能把普通变量硬传给要求 immediate 常量的 intrinsic；应选择变量 permute、少量分支模板，或重新设计算法。

Byte shuffle 可当作小查表，但每半只有 16 个入口

_mm256_shuffle_epi8(data, control) 对输出字节 i 的规则为：若 control[i] 的 bit7 为 1，输出 0；否则取同一个 128 位子块中 control[i] & 0x0f 位置的字节，bits4..6 不参与索引。

因此索引 16 并不会访问低半之外的第 17 个字节，而是选择本半的第 0 个字节。若用它实现 nibble lookup，通常把相同的 16 字节查表复制到两半；若处理 32 入口查表，需要额外的跨半选择与合并。

Unpack 和 pack 也保留这个中间边界

unpacklo_epi32(a,b) 得到 [a0,b0,a1,b1 | a4,b4,a5,b5]，不是把整个 256 位的前四项都交错。packs_epi32(a,b) 把 signed int32 饱和收窄为 int16，输出顺序是 [a0..a3,b0..b3 | a4..a7,b4..b7]。

重排代码最可靠的起点是写出索引数组，并用 0..N-1 的唯一值做测试。真实业务值可能重复，会掩盖错误的 lane 顺序。

8. 数值转换、扩宽、收窄与位移

需求 常用方式 容易遗漏的语义
原位解释相同 bits _mm256_castsi256_ps 等 cast 没有数值转换
int32 → float _mm256_cvtepi32_ps 大于 2²⁴ 的整数可能不能被 float 精确表示
float → int32 _mm256_cvtps_epi32 使用 MXCSR 舍入模式
float → int32，向零截断 _mm256_cvttps_epi32 不等于 round；NaN / 越界有指令异常与 indefinite 结果语义
uint32 → uint64 _mm256_cvtepu32_epi64 输入是 128 位的 4 个 uint32，输出 4 个 uint64
int32 → int64 _mm256_cvtepi32_epi64 符号扩展；不能与 unsigned 版本混用
收窄 pack / shuffle / mask 组合 区分饱和、截断与输出的子块顺序

cvttps_epi32 的失效结果常为 0x80000000（masked invalid 时的 integer indefinite），而这个位型又是合法 INT_MIN。不能仅凭结果等于 INT_MIN 判断输入是否合法，应在转换前检查范围 / NaN，或使用业务允许的明确边界策略。

SIMD 位移不总是遵循标量计数取模

_mm256_slli_epi32 对所有元素使用同一个 immediate；_mm256_sllv_epi32 使用各元素自己的计数。AVX2 有 32 / 64 位逻辑变量位移和 32 位算术右移，但没有通用的逐元素 64 位算术右移版本。

对 32 位逻辑 SIMD 位移，计数达到或超过 32 时结果为零，不是先对计数取 &31。算术右移还要按对应指令的符号填充规则理解。与此同时，C++ 标量移位计数超宽是未定义行为，不能用 x << 32 当测试参考。

命名中的 si256 也不表示“把整个 256 位当成一个大整数”：_mm256_slli_si256 实际按 128 位子块做字节移动。位移、shuffle 和跨 128 位块搬运是不同的工具。

9. Horizontal 运算与真正的全向量归约

hadd 只是按特定顺序配对相加，不是“一条指令把 8 个值求和”。例如 _mm256_hadd_ps(a,b) 的结果为 [a0+a1,a2+a3,b0+b1,b2+b3 | a4+a5,a6+a7,b4+b5,b6+b7]。重复 hadd 仍需处理两个 128 位子块的合并。

常见做法是让热循环只做垂直加法，保留多个独立 accumulator，最后执行一次横向归约。这样减少了循环内重排，也缩短了单条依赖链。

这段使用 AVX，最后落到 128 位再合并为一个 float。它适合说明执行顺序，但 与逐元素从左到右的 scalar sum 不保证逐位一致。需要明确的误差容忍度、可重现求和、double accumulator 或补偿算法时，应先选择数值契约，再选择 SIMD 实现。

整数求和也要决定累加器宽度。8 个 uint32 的和最多需要 35 位；如果先用 32 位向量加法溢出了，再转换成 64 位无法挽回丢失的高位。需要精确宽和时，应先扩宽再累加，并对整个数组的总范围作约束。

前缀和、min/max reduction、dot product、filter compaction 都可以从这些模式组合，但它们的数据依赖不同，不应把一个水平加法模板原样套到所有任务。

10. 运行时分派：不支持 AVX2 的机器也要能启动

CPU 宣告支持 AVX 还不够，操作系统需要启用 XSAVE / OSXSAVE，并在 XCR0 中允许 XMM 和 YMM 状态。手写检测通常涉及 CPUID、OSXSAVE 检查、再执行 XGETBV 检查 (XCR0 & 0x6)==0x6；不能在不满足前提时盲目执行 XGETBV。

对 FMA 路径独立检查 AVX 和 FMA；avx2 通过不能替代 fma 检查。在 ELF IFUNC resolver 或某些早于编译器初始化的特殊场合使用 GCC builtin，需要按文档先调用 __builtin_cpu_init()；普通 main 之后的调用与此不同。

AVX 与 SSE 的边界

某些 CPU 在脏 YMM 高半状态与 legacy SSE 编码之间切换会有额外成本；编译器通常在合适边界插入 vzeroupper。不要在热循环每轮手动清零高半，或把所有 XMM 运算都当成 legacy SSE：AVX 编译模式下的 128 位 intrinsic 也可能使用 VEX 编码。

11. 性能分析：先找瓶颈，再数指令

SIMD 最适合大量元素执行相同操作、地址容易预测、分支可转为 mask 的热点。它的收益由多个限制共同决定：

限制 典型现象 可考虑的方向
内存带宽 大数组相加速度主要随读写字节数变化 减少中间数组、融合遍历、调整布局
缓存 / TLB miss gather、随机 lookup 的延迟占主导 改善局部性、批处理、适量预取
指令吞吐 数据在 L1 中仍被某类指令限制 减少昂贵重排，查目标 CPU 的吞吐和端口
依赖链延迟 单 accumulator 的串行链很长 适量展开、多个独立 accumulator
分支 / 选择输出 命中率改变时性能波动 比较 branch、mask、bitset 和压缩策略
调用与尾部开销 很小的 n 上向量版更慢 小规模标量路径，减少分派开销

数组相加每个 float 至少涉及两个读和一个写的逻辑流量，即 12 字节；实际内存总线流量还受 write allocate、缓存状态和存储策略影响。8 lane 指令并不会把这些数据搬运需求除以 8。

Latency 决定依赖链上的等待，reciprocal throughput 描述独立指令能以多高频率发射 / 完成；二者不能互换。一条 256 位指令可能拆成多个微操作，不同 Intel / AMD CPU 的执行宽度和 shuffle 成本也可能不同。

自动向量化是必须比较的基线

先给编译器清楚的循环、别名契约和数据布局，查看是否已经自动向量化。GCC 可使用 -fopt-info-vec-optimized -fopt-info-vec-missed，Clang 可使用 -Rpass=loop-vectorize -Rpass-missed=loop-vectorize。

手写 intrinsic 应与同样优化等级、合理 aliasing 信息和数值语义的自动向量化版本比较。不能只拿 -O0 标量代码作对照，或把禁止向量化的参考实现说成编译器的最佳表现。若确实需要严格 scalar 基线，单独控制 loop / SLP vectorization，并说明这是实验对照。

一个可复核的测量应包含什么

  1. 先验证结果和边界，再计时；使用循环外初始化的输入，确保输出被消费，避免死代码删除。
  2. 分开测试小数组、L1/L2/LLC 内数组和超出缓存的大数组，记录长度、对齐、命中率 / 索引分布。
  3. 重复测量，报告分布或中位数；控制线程迁移、并发负载与预热条件，必要时记录 cycles、instructions、cache misses。
  4. 查看汇编，确认期望的向量宽度、加载、FMA 和尾部路径确实生成；注意 register spill 和代码体积。
  5. 对齐业务的端到端时间。更宽向量还可能影响部分 CPU 的频率，局部 kernel 的收益不直接等于整个查询的收益。

本文不给未经测量的加速倍数。完整程序是正确性演示，不是严谨的 benchmark；测试机器为虚拟化环境，其结果也不应冒充某款 CPU 的裸机吞吐指标。

12. 完整源码、验证与继续阅读

下载 simd_examples.cpp。它包含 AVX 数组相加、uint32 比较计数、maskload 尾部、浮点归约、FMA，以及针对构造顺序、shuffle、扩宽乘法、gather、变量位移的检查。

g++ -std=c++17 -O3 -Wall -Wextra -Werror -ffp-contract=off \
  simd_examples.cpp -o simd_examples
./simd_examples

不要为这份带 dispatcher 的示例加全局 -mavx2。它依靠函数级 target attribute 生成多个 ISA 路径。

本次在 Intel Xeon Platinum 8260 的 KVM 环境中使用 GCC 12.2 与 Clang 22.1.8 编译运行。检查覆盖长度 0..257、非 32 字节对齐起点、全部尾长、uint32 符号边界 / 相等值、NaN ordered 比较，以及掩码尾部位于不可访问页前的情形。另运行 AddressSanitizer / UndefinedBehaviorSanitizer；当前执行环境不支持 LeakSanitizer，使用 ASAN_OPTIONS=detect_leaks=0。

从基础指令走向 Velox

Velox 的 SimdUtil.h 使用 xsimd 和架构模板组织 SIMD 能力。例如 byteSetBits 提供 bitset 到位置数组的查表，服务于索引提取 / permute；kPadding 又体现了数据结构为了完整宽度访问预留空间的专门契约。

这些都建立在本文的 mask、索引、重排和访存边界之上，但通用数组循环不能直接假设自己也拥有 Velox 内部 buffer 的 padding。后续可结合 SIMD in Velox 看实际过滤器如何组织批处理。
